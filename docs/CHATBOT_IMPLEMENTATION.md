# ⁧راه‌اندازی و محدودهٔ چت‌بات GreenPeak

⁧چت با دکمهٔ دایره‌ای شناور در پایین سمت راست صفحات کاربران واردشده باز می‌شود. پنجره در همان صفحه باقی می‌ماند و روی موبایل نیز قابل استفاده است. انتخاب داده‌های سایت یا یک اتصال MT5، تاریخچه، گفت‌وگوی جدید و حذف گفت‌وگو در همین پنجره قرار دارند.

## ⁧پیکربندی

⁧تنظیمات ارائه‌دهنده از همان تنظیمات تحلیل موجود در `.env` ریشهٔ مخزن خوانده می‌شوند:

```dotenv
GREENPEAK_LLM_PROVIDER=openai-compatible
GREENPEAK_LLM_BASE_URL=https://your-compatible-provider.example/v1
GREENPEAK_LLM_MODEL=your-model-name
GREENPEAK_LLM_API_KEY=your-private-key
GREENPEAK_CHAT_RETENTION_DAYS=30
GREENPEAK_CHAT_DAILY_LIMIT=100
GREENPEAK_CHAT_MT5_STALE_MINUTES=5
```

⁧ارائه‌دهنده باید قرارداد فعلی `generate_json` پروژه را پشتیبانی کند: پاسخ JSON برای درخواست‌های `chat/completions` با `response_format=json_object`. هر پاسخ چت حداکثر دو فراخوانی مدل و چهار بازیابی داده دارد. پس از تغییر تنظیمات، بک‌اند باید دوباره اجرا شود. کلید مدل صرفاً در بک‌اند نگهداری می‌شود.

⁧تاریخچه و سهمیه در SQLite ذخیره می‌شوند؛ مسیر پیش‌فرض `backend2/instance/chat/chat.db` است و با `GREENPEAK_CHAT_DB_PATH` قابل تغییر است. اسکریپت دیپلوی پوشهٔ چت را به مسیر پایدار روی سرور پیوند می‌دهد تا تاریخچه با انتشار نسخهٔ جدید حفظ شود. برای مسیر سفارشی نیز دیسک پایدار لازم است. این ذخیره‌سازی برای یک میزبان برنامه با چند worker مناسب است؛ اجرای چند replica مستقل نیازمند ذخیره‌سازی مشترک و بازطراحی این لایه است.

⁧محدودیت پیش‌فرض ۱۰ درخواست در دقیقه و ۱۰۰ تلاش در ۲۴ ساعت گذشته برای هر کاربر است. تلاش‌های ناموفق نیز سهمیه مصرف می‌کنند. هر کاربر حداکثر ۱۰۰ گفت‌وگو و هر گفت‌وگو حداکثر ۵۰ نوبت دارد. ۵ نوبت آخر برای زمینهٔ مدل استفاده می‌شوند. پاک‌سازی گفت‌وگوهای قدیمی هنگام استفاده از تاریخچه انجام می‌شود؛ حذف دستی نیز پشتیبانی می‌شود.

## ⁧داده‌ها و دسترسی

⁧بازیابی داده از فهرست ابزارهای خواندنی انجام می‌شود: ویژگی شاخص، تحلیل ذخیره‌شده، دادهٔ تاریخی قیمت S&P 500، خبرهای ذخیره‌شدهٔ Alpha Vantage، تقویم آیندهٔ سایت، وضعیت حساب و پوزیشن‌های باز. متن پاسخ فارسی و ارجاع‌ها با قرارداد Pydantic اعتبارسنجی می‌شوند؛ جدول حساب و پوزیشن‌ها مستقیماً از دادهٔ بک‌اند نمایش داده می‌شود.

⁧برای شاخص‌ها، snapshot محاسباتی ذخیره‌شده منبع اول است. مجموعه‌ای از adapterهای موجود سایت نیز در نبود snapshot استفاده می‌شوند. برای ورودی سازگار، ویژگی‌ها فقط با موتور Python موجود و بدون ذخیره‌کردن snapshot تولید می‌شوند. اگر واحد یا سری منبع با تعریف متفاوت باشد، فقط داده و متادیتای واقعی API ارائه می‌شود و ویژگی مشتق‌شده تولید نمی‌شود. شاخص فاقد دادهٔ قابل بازیابی فقط تعریف و محدودیت دارد.

⁧فهرست حساب‌ها از اتصال‌های فعال متعلق به کاربر ساخته می‌شود. بازیابی snapshot با هویت کاربر، شناسهٔ اتصال و هویت کامل بروکر/سرور/حساب محدود می‌شود؛ اتصال قبل و بعد از تولید پاسخ دوباره بررسی می‌شود. انتخاب حساب پیش از ساخت گفت‌وگو به پذیرش پردازش اطلاعات لازم توسط ارائه‌دهندهٔ مدل نیاز دارد. رمزها، توکن‌ها، شمارهٔ حساب کامل، شناسهٔ معامله و توضیحات خصوصی معامله به مدل ارسال نمی‌شوند.

⁧گفت‌وگو به محدودهٔ انتخاب‌شده وابسته است. تغییر حساب یا تغییر بین سایت و حساب، گفت‌وگوی تازه‌ای ایجاد می‌کند. قطع اتصال جلوی تولید پاسخ جدید برای آن اتصال را می‌گیرد؛ تاریخچهٔ قبلی تا زمان حذف یا پایان دورهٔ نگهداری برای مالک قابل مشاهده است.

⁧نسخهٔ فعلی اجرای معامله، جست‌وجوی آزاد اینترنت، تحلیل عملکرد تاریخی، محاسبهٔ زیان تا حد ضرر و تطبیق تأییدنشدهٔ نماد بروکر با دارایی سایت را پشتیبانی نمی‌کند. فیلتر نماد پوزیشن با نام دقیق نماد بروکر انجام می‌شود. حداکثر ۵۰ پوزیشن مرتب‌شده براساس سود و زیان نمایش داده می‌شوند و تعداد کل نتایج مشخص است.

## ⁧مسیرهای API

```text
GET    /api/v1/chat/status
GET    /api/v1/chat/accounts
GET    /api/v1/chat/conversations
POST   /api/v1/chat/conversations
GET    /api/v1/chat/conversations/{conversation_id}
DELETE /api/v1/chat/conversations/{conversation_id}
POST   /api/v1/chat/conversations/{conversation_id}/messages
```

⁧همهٔ مسیرها به توکن Bearer نشست کاربر نیاز دارند. پیام با `request_id` از نوع UUID فرستاده می‌شود؛ تکرار همان پیام با همان شناسه پاسخ ذخیره‌شده را برمی‌گرداند. مالکیت گفت‌وگو و حساب سمت سرور بررسی می‌شود و پاسخ‌های خصوصی قابل cache نیستند.

## ⁧بررسی کیفیت

⁧تست‌های `backend2/tests/test_chat.py` کنترل دسترسی، رضایت پردازش حساب، قطع اتصال، تکرار پیام، محدودیت مصرف، نگهداری تاریخچه و محدودکردن ابزارهای مدل را بررسی می‌کنند. برای ارزیابی پاسخ زبانی با ارائه‌دهندهٔ واقعی، کلید مدل و دادهٔ حساب آزمایشی متعلق به ارزیاب لازم است. تست با مدل شبیه‌سازی‌شده جای این ارزیابی را نمی‌گیرد.
